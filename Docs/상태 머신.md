# 플레이어 상태 머신

## 실행 책임

`CharacterStateMachine`이 상태 객체를 소유하고 입력 요청을 판정합니다. `CharacterController`는 컴포넌트 참조를 제공하며 `GetState<T>()`를 상태 머신에 위임합니다.

- 상태의 `CanEnter()`가 현재 조건에서 진입 가능한지 판정합니다.
- 현재 상태의 `CanExit(next)`가 해당 후보로 중단/종료할 수 있는지 판정합니다.
- 두 조건을 만족하는 후보 중 `Priority`가 높은 상태를 선택합니다. 동순위에는 현재 상태를 유지합니다.
- 전환은 이전 상태의 `Exit()`, 현재 상태 교체, 다음 상태의 `Enter()` 순서로 수행합니다.
- 같은 상태를 유지할 때는 재진입하지 않습니다. 상태의 프레임 처리와 물리 처리를 상태 머신이 호출합니다.

현재 우선순위는 Idle 0, Walk/Run/Jump/Fall 1, Attack 2, HitStun 3입니다. 조건이 끝난 공격·피격은 낮은 우선순위의 이동 상태로 돌아갑니다. 낙하 중에도 공격 요청이 허용됩니다.

## 입력 및 전투

`PlayerInputListener`의 Z/X 이벤트는 상태 머신의 요청 큐로 들어갑니다. `RequestAttack(AttackInput)`으로도 요청할 수 있습니다. 같은 판정 시점의 피격 요청은 공격보다 우선하며, 거절된 공격은 피격 종료 후 재생하지 않습니다.

공격 상태 진입 시 준비된 첫 공격을 실행합니다. `AttackState.Update()`가 기존 공격 타임라인과 콤보를 진행합니다. 후속 콤보는 같은 AttackState를 유지하므로 Enter/Exit를 반복하지 않습니다. 기존 입력 창과 첫 유효 입력 예약 정책을 유지합니다.

공격 도중 이동과 점프는 잠깁니다. 지상 공격은 `CancelOpen` 이후 좌우 이동 입력으로 취소할 수 있으며, 착지까지 유지하는 공격은 이동으로 취소하지 않습니다. 공격 상태 종료는 타임라인과 예약 입력을 정리합니다. 비활성화도 동일한 정리 경로를 사용합니다.

`RequestHitStun(duration)`은 초 단위 피격 경직 요청입니다. 피격 시 공격과 예약 입력을 취소하고 이동·점프를 잠급니다. 연속 피격은 현재 남은 시간과 새 요청 중 긴 시간을 적용합니다. 현재 피격 전용 애니메이션은 없으므로 대기 모션을 사용합니다. 데미지·넉백·다운·궁극기 구현은 이 변경에 포함하지 않습니다.

점프는 누름 시점의 버퍼로 실행합니다. 잠금 상태에서 누른 점프는 폐기하며, 키를 계속 누른다고 잠금 해제 후 자동 점프하지 않습니다. 기존 코요테 타임과 점프 버퍼 시간은 유지합니다.

## 상태와 이동 상황 조회

`CurrentState`와 `CurrentStateInstance`는 현재 행동 상태를 조회합니다. `RefreshState()`는 호환용 읽기 메서드이며 상태를 변경하지 않습니다.

`GetLocomotionState()`는 행동 상태와 독립적으로 접지·수직 속도·방향 입력을 조회합니다. 하강 시 Fall을 반환합니다. 공격 종류 선택에는 대시 점프 출발 정보도 유지합니다. `IsGrounded`로 착지 여부를 직접 판단하므로 Attack 상태에서도 착지로 공격을 종료할 수 있습니다.

애니메이션은 상태 진입과 공격 타임라인에서 구동합니다. Jump/Fall은 기존 점프 애니메이션을 사용합니다. 기본 공격 데이터가 없는 대시 공격 등의 슬롯에는 기존과 같이 공격을 실행하지 않습니다.

## 검증

Unity Edit Mode에서 `Tools > Chronicles > Validate State Machine and Combat`를 실행합니다. 실제 Theodore 프리팹과 Input System 키보드 이벤트로 이동/더블 탭 대시/점프/낙하, ZZZZ/ZZZX, 스프라이트 샘플링, 공격 취소, 피격 우선순위, 착지, 비활성화/재활성화를 검사합니다. 검증 중 Play Mode로 진입한 뒤 복귀합니다.

배치 실행은 `-batchmode -nographics -projectPath <프로젝트 경로> -executeMethod CombatAnimationValidation.Run -logFile <로그 경로>`를 사용합니다. 검증기가 완료 시 에디터를 종료하므로 `-quit`을 함께 지정하지 않습니다.
